# M3

Add data collection. Three independent collectors, each toggleable.

## Design decision
The loop currently sleeps 60s, which is too slow to see keystrokes.
Switch to polling: read all 256 virtual keys via GetAsyncKeyState every 15ms.
Leave a comment marking where a WH_KEYBOARD_LL hook would replace this later.

## Keylogger
- Capture all 256 virtual keys.
- Track the foreground window. When it changes, record the window title.
- Buffer in memory. Flush to keys.log on window change or every 30s.
- Never write once per keystroke.

## Screenshots
- Capture the primary screen every 5 minutes into screenshots/.
- No third-party libs. Use ctypes with user32/gdi32 BitBlt into a DIB section,
  then write a BMP by hand with struct.
- Filename: timestamp.bmp

## Clipboard
- Detect changes cheaply with GetClipboardSequenceNumber.
- On change, read CF_UNICODETEXT and append to clipboard.log.
- The clipboard is often locked by another process. Retry a few times, then
  skip. Never crash.

## Rules
- stdlib only, ctypes allowed.
- Each collector independently testable and toggleable:
  --no-keys, --no-screen, --no-clip
- All output lives in the existing hash folder.
- Log rotation and OSError suppression apply to every new file.
- A failing collector must log and continue, never raise.

## Done when
- Typing appears in keys.log with the correct window title.
- A .bmp appears after the interval and opens in Paint.
- Copying text appends to clipboard.log.
- CPU stays under 2% while typing.

## Tests
- vkey mapping produces the expected character for a known keycode.
- screenshot BMP header is valid and dimensions match the screen.
- a clipboard sequence-number change triggers exactly one append.
